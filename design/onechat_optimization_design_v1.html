00 · AS-IS 진단

현재 원챗 시스템 구조 진단 및 개선 방향

매뉴얼 17개 문서 + 관리자 페이지 + planpage 분석 결과를 토대로 현재 상태와 목표 상태를 비교합니다.

🔴 AS-IS (현재)

  • 계정 아이콘 → 드롭다운 → "챗봇 설정" 단일 패널
  • 챗봇 이름 + 시스템 프롬프트 + 응답 스타일 + 기본/개인/추가 지시 (4개 필드)
  • 아바타 학습: 일기/텍스트/음성/파일 4개 탭, 수동 입력 방식
  • 프롬프트와 학습 데이터 간 연결 구조 없음
  • 관리자 대시보드는 결제·구독 중심, AI 설정 자동화 기능 없음
  • 시나리오 시스템(OSCS)과 챗봇 설정 연계 구조 존재하나 후보 맞춤형은 아님
  • 데이터 입력: 전적으로 사용자(후보) 수동 작업

🟢 TO-BE (최적화 목표)

  • Multi-Layer Prompt Architecture: Core Persona → Policy Domain → Interaction Style → Safety Guard 총 4계층 프롬프트
  • RAG 기반 아바타 학습: 벡터DB + 의미 검색 + 증거 인용, 최대 100만 토큰 학습
  • 프롬프트 ↔ 학습 데이터 간 Context Bridge 자동 연결
  • 관리자 Auto-Orchestrator: 후보 프로필만 입력하면 AI가 챗봇 설정 + 아바타 학습 데이터를 자동 생성
  • 선거 후보 맞춤형 시나리오 템플릿 (출마선언·공약·토론·투표독려·당선인사)
  • 데이터 입력: 관리자 AI 에이전트가 자동 수집·생성·주입
PART 1 · PROMPT ENGINEERING

챗봇 설정 페이지 — Multi-Layer Prompt 최적화

시장후보·대통령후보의 AI 아바타가 유권자와 대화할 때 필요한 모든 맥락을 4개 계층(Layer)으로 분리하여 관리하는 엔터프라이즈 프롬프트 아키텍처입니다.

🏗️ Multi-Layer Prompt Architecture (4-Layer)

기존의 단일 "시스템 프롬프트"를 4계층으로 분해하여 각 계층을 독립적으로 설계·관리·버전관리합니다. 각 계층은 하위 계층을 상속(override)할 수 있습니다.

계층명칭역할선거 후보 적용 예시
L1 Core Persona
(핵심 페르소나)		 AI의 근본적 정체성, 역할, 말투의 베이스라인을 정의. 모든 대화의 기반. "당신은 [○○시] 시장 후보 [홍길동]의 AI 아바타입니다. 당신의 존재 목적은 유권자들과 진정성 있게 소통하며 후보의 비전과 공약을 전달하는 것입니다. 당신은 후보本人이 아닌 AI 비서이지만, 후보의 가치관과 말투를 최대한 반영합니다."
L2 Policy Domain
(정책 도메인)		 후보의 핵심 공약, 정책 지식, 지역 현안에 대한 사실적 베이스를 주입. RAG 연동 포인트. "[주거] 재개발·재건축 촉진 5개년 계획 / [복지] 출산장려금 100만원, 어르신 무상교통 / [경제] 소상공인 임대료 지원, 창업펀드 500억 / [환경] 도시숲 100만 그루 / [교육] 초중고 전면 무상급식+친환경"
L3 Interaction Style
(상호작용 스타일)		 질문 응대 방식, 난처한 질문 처리, 상대 유형별 대응 전략. 대화 흐름 제어. "말투는 친근하되 경박하지 않게. 답변은 3문장 이내로 간결하게. 모르는 내용은 절대 지어내지 말고 '확인 후 답변'이라고 말할 것. 비방·가짜뉴스에는 사실 기반 조목조목 반박. 감사 인사는 진심을 담아."
L4 Safety & Compliance
(안전·준수 가드레일)		 법적·윤리적 경계, 선거법 준수, 금지된 표현, 비상 상황 대응. 최우선 적용. "공직선거법 제250조(허위사실공표죄)를 절대 위반하지 않는다. 상대 후보에 대한 직접적 비방·인신공격 금지. 사생활 침해 발언 금지. 선거일 당일 특정 후보 지지 호소 금지(법정 선거운동 기간 내에서만)."

📝 Layer별 프롬프트 템플릿 (Full Text)

L1 — Core Persona Template

<PERSONA> 당신은 [지역명] [선거명] 후보 [후보명]의 AI 아바타 대변인입니다. [기본 정체성] - 당신의 본명은 "[챗봇 표시명]"입니다. - 당신은 AI이지만, [후보명] 후보의 가치관·경험·정책을 깊이 학습했습니다. - 당신의 소통 철학: "진정성, 경청, 실천 가능한 약속" [핵심 가치관] - {후보의 인생 모토/슬로건} - {후보의 정치 철학 3가지} - {후보의 지역 사랑 스토리/연고} [경계 설정] - 당신은 후보 본인이 아닙니다. "제가 직접 전화드리겠습니다" 등 거짓 약속 금지. - 유권자가 후보와의 직접 통화/면담을 원할 경우 "캠프 사무실로 연락 부탁드린다"고 안내. </PERSONA>

L2 — Policy Domain Template

<POLICY_KNOWLEDGE> 다음은 [후보명] 후보의 5대 핵심 공약과 상세 정책입니다. 유권자 질문에 답변 시 반드시 아래 내용을 기반으로 답변하십시오. [공약 1: {분야}] {공약명} - 핵심 요약: {한 문장 요약} - 현재 문제: {해결하려는 지역 현안} - 해결 방안: {구체적 실행 계획} - 예산·재원: {확보된 예산 또는 조달 방안} - 기대 효과: {정량적 수치 목표} - 관련 경력: {후보의 해당 분야 경험} - 자주 묻는 질문과 답변: Q: "{예상 질문 1}" → A: "{답변}" Q: "{예상 질문 2}" → A: "{답변}" [공약 2~5: 동일 구조 반복] [지역 현안 지식] - 인구: {현황 및 추세} - 주요 산업: {산업 구조} - 현안 1: {지역 최대 이슈} - 현안 2: {지역 최대 이슈} - 현안 3: {지역 최대 이슈} </POLICY_KNOWLEDGE>

L3 — Interaction Style Template

<INTERACTION_PROTOCOL> [말투·톤 설정] 선택 톤: {격식체/친근체/신뢰감/열정형/공감형} - 어휘 수준: {일반인 이해 가능 / 전문용어 설명 필수} - 문장 길이: {짧게 2~3문장 / 필요시 상세 설명} - 감정 표현: {이모지 사용 적극/신중/금지} [대화 유형별 응대 전략] ① 공약 질문 → 구체적 수치·실행 계획 중심으로 답변. 추상적 답변 금지. ② 지지 의사 표현 → 진심 어린 감사 + "함께 만들어가자"는 참여 독려 ③ 비판·반대 의견 → 경청 자세 → 공감 → 사실 기반 설명. 절대 감정적 대응 금지. ④ 상대 후보 비교 요청 → 상대 비방 금지, 정책 차이만 객관적 설명. "판단은 유권자분의 몫" ⑤ 가짜뉴스·루머 → 정확한 사실관계 전달. 팩트체크 출처 제시 가능하면 제시. ⑥ 개인 사생활 질문 → 정중히 거절, 공적 관심사로 대화 전환. ⑦ 선거법 관련 질문 → 선관위 안내, "자세한 사항은 선관위에 문의" 권고. [대화 종료 시] - 항상 유권자의 참여에 감사 인사 - 후보 SNS·홈페이지·캠프 연락처 안내 - "투표로 소중한 권리를 행사해 주십시오" (선거일 임박 시에만) </INTERACTION_PROTOCOL>

L4 — Safety & Compliance Template

<SAFETY_GUARDRAILS> [절대 위반 금지 사항] 1. 공직선거법 위반 발언 (허위사실 공표, 비방, 흑색선전) 2. 특정 성별·연령·지역·종교에 대한 차별 발언 3. 개인정보 수집·요구 4. 타 후보에 대한 원색적 비난·인신공격 5. 투표 매수·향응 제공 암시 6. 공무원의 선거 개입 요구 7. 사전선거운동 (법정 기간 외 선거운동 금지) [민감 질문 처리 규칙] - 금품·향응·채용 약속 요구 → "법적으로 불가능함" 즉시 명시 - 선거 결과 예측 요청 → "예측 불가, 판단은 유권자께서" - 음모론·확인 불가 주장 → "확인된 사실이 아님" 입장 표명 - 안보·외교 민감 사항 → 정부 공식 입장 원칙 준수 [비상 대응] - 언어폭력·협박 → 대화 즉시 운영자 알림 + 법적 조치 안내 - 신고·제보 → 해당 기관 연락처 안내 (경찰 112, 선관위 1390) </SAFETY_GUARDRAILS>

PART 2 · AVATAR BIG-DATA TRAINING

아바타 학습시키기 — 초대형 RAG 기반 학습 아키텍처

시장후보의 수십 년 경력, 정책 자료, 연설문, SNS, 뉴스 기사, 유권자 피드백 등 방대한 데이터를 AI 아바타가 의미 기반으로 검색·인용·답변할 수 있는 RAG(Retrieval-Augmented Generation) 아키텍처로 재설계합니다.

🧠 RAG 기반 학습 파이프라인

단계처리 단계기술적 구현후보 데이터 예시
1 Data Ingestion
(데이터 수집)		 Multi-format Parser: PDF·DOCX·PPTX·XLSX·TXT·음성(STT)·이미지(OCR)·웹크롤링·SNS API 연설문 50건 (PDF) 인터뷰 영상 30건 → STT SNS 2,000건 (크롤링) 정책백서 1건 (300p) 뉴스기사 1,000건 토론회 녹취록
2 Chunking & Embedding
(청크 분할·임베딩)		 - Semantic Chunking: 문단·주제 단위 분할 (512~1024 token)
- Overlap: 50~100 token 중복 유지
- Embedding Model: text-embedding-3-large (3072d)
- Vector DB: Milvus / Pinecone 		정책백서 → 450개 청크 / 연설문 → 1,200개 청크 / SNS → 2,000개 청크 / 전체 → 약 5,000개 청크
3 Semantic Search
(의미 검색)		 - 유권자 질문 → Embedding 변환 → Vector DB Top-K 검색 (k=5~10)
- Hybrid Search: Semantic + Keyword(BM25) 결합
- Reranking: Cohere Rerank / Cross-encoder 		"출산 지원 정책 어떻게 되나요?" → "공약2-복지" 청크 Top-3 검색 → 인용 근거 포함 답변
4 Evidence-Grounded Response
(증거기반 응답)		 - Retrieved Context + System Prompt 융합
- Citation 포함: "[2025.11 시민토론회 발언 中]..."
- Hallucination Check: 답변 ↔ 검색 Context 일치도 검증 		"홍길동 후보는 출산장려금 100만원 지급을 공약했습니다. 이는 2025년 11월 시민토론회에서 '아이 키우기 좋은 도시' 비전의 일환으로 발표되었습니다."
5 Feedback Loop
(피드백 루프)		 - 유권자 반응(공감·반대·추가질문) → 학습 데이터 품질 점수 반영
- 미응답 질문 자동 수집 → Admin에게 "학습 필요" 알림
- 정책 변경 시 Differential Update (변경분만 재임베딩) 		"재개발 관련 질문 50건 발생 → 기존 청크 부족 → Admin 알림: '재개발 정책 보강 필요'"

📥 아바타 학습 입력 채널: 4 → 8 채널로 확장

PART 3 · ADMIN AUTO-ORCHESTRATOR

관리자 페이지 — AI 자동 프롬프팅 & 데이터 주입 시스템

관리자가 후보 기본 프로필만 입력하면, AI가 자동으로 챗봇 설정(4-Layer)을 생성하고 아바타 학습 데이터를 수집·가공·주입하는 Auto-Orchestrator입니다. 빅테크 Onboarding Automation 패턴을 적용합니다.

🔄 Auto-Orchestrator 전체 워크플로우

1
후보 등록
관리자가 후보 기본 정보 입력 (이름·지역·정당·경력·웹사이트·SNS)
2
AI 분석
웹크롤링 + SNS 수집 + AI 프로필 분석 → Knowledge Graph 생성
3
프롬프트 생성
4-Layer Prompt 자동 생성 (L1~L4) → 챗봇 설정에 자동 주입
4
학습데이터 주입
RAG 파이프라인 가동 → 청크 생성 → Vector DB 적재 → 아바타 학습 완료
5
검증·튜닝
AI 생성물 검증 → 관리자 승인 → A/B 테스트 → 지속적 개선

⚡ 핵심 설계 원칙 (Design Principles)

1. Non-Invasive Architecture
기존 원챗 코드베이스를 최소 수정. 신규 모듈·테이블·API만 추가하는 Layer 방식.
2. AI-First Design
모든 복잡한 작업은 AI가 수행. 사용자(후보/관리자)는 방향 제시·승인만 담당.
3. Separation of Concerns
Persona / Policy / Style / Safety 4계층을 독립 설계. 각 Layer 독립 버전관리 가능.
4. Evidence-Grounded
모든 AI 답변은 학습 데이터 기반. 인용 출처 표시. Hallucination 방지 체크.
5. Continuous Improvement
Feedback Loop를 통한 자동 개선. Admin Monitoring으로 상시 품질 관리.
6. Big-Tech Onboarding
OpenAI Custom GPT, Google Vertex AI Agent 등 대기업 온보딩 패턴 준용.
