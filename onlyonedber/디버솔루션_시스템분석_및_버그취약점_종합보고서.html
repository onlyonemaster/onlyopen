4.1 #1 Process Deadlock (FormDownloader.cs:520-540)

현재 코드 (문제): 
Process process = Process.Start(new ProcessStartInfo {
    FileName = directoryName, Arguments = "--version",
    UseShellExecute = false, CreateNoWindow = true,
    RedirectStandardOutput = true, RedirectStandardError = true
});
string text = process.StandardOutput.ReadToEnd();  // ← stderr 버퍼 가득 차면 여기서 영구 대기
string text2 = process.StandardError.ReadToEnd();
process.WaitForExit();
이유: StandardOutput.ReadToEnd()는 자식 프로세스의 stdout 스트림이 닫힐 때까지 대기하는데, 자식 프로세스가 stderr에 대량 출력 중이면 stderr 버퍼(4KB)가 가득 차서 프로세스 자체가 블로킹됨 → 결과적으로 부모도 자식도 서로를 기다리는 데드락 발생.
수정 방안: stdout/stderr를 비동기로 읽거나, 별도 스레드에서 읽은 후 WaitForExit(timeout) 사용. source_recovered 버전에서 이미 부분적으로 수정되었으나 완전하지 않음.

// .github/workflows/build.yml 예시
name: Build OnlyoneDBer
on: [push]
jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: '8.0.x' }
      - run: dotnet restore OnlyoneDBer.sln
      - run: dotnet build OnlyoneDBer.sln -c Release
      - uses: actions/upload-artifact@v4
        with: { name: onlyonedber-release, path: '**/Release/**/*.exe' }
