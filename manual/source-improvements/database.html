🗄️ DB 테이블 구조 완전 분석

source_improvements 테이블의 21개 컬럼 상세 구조와 DB 연결 방식을 분석합니다.

테이블 스키마

#컬럼타입용도
1idint (PK)자동 증가 식별자
2datedate개선 작업일 (필터 기준)
3projectvarchar(50)프로젝트 분류
4categoryvarchar(50)버그수정/기능추가/성능개선/보안/리팩토링/문서화
5titlevarchar(200)개선 항목 제목
6descriptiontext상세 설명 (마크다운 스타일)
7developervarchar(50)개발자 이름
8files_changedint변경 파일 수
9lines_addedint추가된 코드 라인
10lines_deletedint삭제된 코드 라인
11statusvarchar(20)개발중/완료/테스트중/배포됨/롤백
12test_resultvarchar(10)PASS/FAIL
13environmentsvarchar(50)dev/test/prod (콤마구분)
14deployed_datedatetime실제 배포 일시
15deployed_byvarchar(50)배포자
16deployment_logtext배포 로그 (선택)
17notice_idint연동된 공지사항 ID
18impact_levelvarchar(10)낮음/중간/높음/긴급
19notestext추가 메모
20created_atdatetime등록 시간
21updated_atdatetime수정 시간

DB 연결 방식

// db_config.php 흐름
1. 파일경로 판단 (__DIR__)
   ├── /disk/daily/xxx  → 개발환경 강제 보호 발동
   │   ├── LOCAL 전환
   │   ├── 소켓: /disk/daily/home/kiamdb/mysql_dev.sock
   │   └── 포트: 3307
   └── 그 외            → db_mode.conf 설정 따름
       ├── MODE=LOCAL   → 소켓: /home/kiamdb/mysql.sock
       └── MODE=REMOTE  → TCP: 116.120.58.86:3306

2. mysqli_connect() → 전역 $self_con
3. mysqli_set_charset('utf8mb4')
💡 핵심 포인트: notice_id 컬럼이 NULL이면 아직 공지로 변환되지 않은 항목입니다. 목록에서는 notice_id가 없는 항목에만 공지 버튼이 표시됩니다.
