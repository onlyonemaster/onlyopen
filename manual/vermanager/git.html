📦 Git/GitHub CI/CD 자동화 운영 가이드

Git 저장소 관리부터 자동 커밋, 시맨틱 버전 태그 생성, GitHub Push까지 완전한 CI/CD 파이프라인을 운영하는 방법입니다.

개념: 4가지 Git 자동화 기능

기능Git 명령API action
자동 커밋git add -A → git commit -m "..."commit
버전 태그git tag -a "v1.0.2" -m "..."tag
GitHub Pushgit push origin main --tagspush
전체 릴리즈Commit → Tag → Push (순차)full-release

1. Git 저장소 상태 확인

UI에서 확인

  1. /vermanager/git?site=kiam-prod 접속
  2. Git 정보 카드 자동 로드:
    • 현재 브랜치 (main)
    • 최신 커밋 해시 + 메시지
    • 변경된 파일 수 (modified, untracked)
    • 최근 태그 5개
    • GitHub 리모트 URL

API로 확인

curl "https://kiam.kr/vermanager/api/git?action=status&site=kiam-prod"

// 응답 예시
{
  "git": {
    "is_repo": true,
    "branch": "main",
    "last_commit": "1cbf11c feat(vermanager): Phase 4-6...",
    "has_changes": false,
    "changed_files": [],
    "recent_tags": ["v1.0.1", "v1.0.0"],
    "remote_url": "https://github.com/onlyonemaster/onlyopen.git"
  }
}

2. 자동 커밋

UI에서 커밋

  1. /vermanager/git?site=kiam-prod → "Git 커밋" 섹션
  2. 커밋 메시지 입력 (예: "fix: 로그인 세션 버그 수정")
  3. "커밋 실행" 클릭 → git add -A + git commit 실행
  4. 결과: 새 커밋 해시 표시

API로 커밋

curl -X POST https://kiam.kr/vermanager/api/git \
  -H "Content-Type: application/json" \
  -d '{"action":"commit","site":"kiam-prod","message":"feat: 새 기능 추가"}'

3. 버전 태그 생성

UI에서 태그

  1. "Git 태그" 섹션에서 버전 입력 (예: 1.0.2)
  2. 태그 메시지 입력 (선택)
  3. "태그 생성" 클릭 → git tag -a "v1.0.2" 실행
  4. 중복 태그 방지: 이미 존재하는 태그는 경고 표시

API로 태그

curl -X POST https://kiam.kr/vermanager/api/git \
  -H "Content-Type: application/json" \
  -d '{"action":"tag","site":"kiam-prod","version":"1.0.2","note":"두 번째 패치 릴리즈"}'

4. GitHub Push

UI에서 Push

  1. "GitHub Push" 섹션에서 현재 브랜치 확인
  2. "Push 실행" 클릭 → git push origin main --tags
  3. Push 결과 (성공/거절/실패) 표시
⚠️ 주의: Push 거절(rejected) 발생 시 원격 저장소에 먼저 pull을 수행해야 합니다. 이 경우 수동으로 충돌을 해결한 후 다시 Push를 시도하세요.

5. 전체 릴리즈 파이프라인 (권장)

UI에서 전체 릴리즈

  1. /vermanager/git?site=kiam-prod → "전체 릴리즈" 섹션
  2. 릴리즈 버전, 커밋 메시지, 태그 노트 입력
  3. "전체 릴리즈 실행" 클릭
  4. 3단계 순차 진행:
    단계작업성공실패
    1단계Git 커밋✅ 커밋: e66b406⏭️ 변경사항 없음 (skip)
    2단계Git 태그✅ 태그: v1.0.2⚠️ 이미 존재함
    3단계GitHub Push✅ Push 완료❌ rejected

API로 전체 릴리즈

curl -X POST https://kiam.kr/vermanager/api/git \
  -H "Content-Type: application/json" \
  -d '{
    "action":"full-release",
    "site":"kiam-prod",
    "version":"1.0.2",
    "commit_message":"🔖 릴리즈 v1.0.2",
    "note":"버그 수정 및 UI 개선"
  }'

6. 자동화 작업 로그

모든 Git 자동화 작업은 data/sites/{id}/git_automation_log.json에 기록됩니다.

// 로그 조회
curl "https://kiam.kr/vermanager/api/git?action=automation-log&site=kiam-prod"

// 로그 항목 구조
{
  "id": "git_664a1b2c3d4e5",
  "site_id": "kiam-prod",
  "action": "full-release",
  "status": "success",
  "timestamp": "2026-05-03T15:30:00+09:00",
  "version": "1.0.1",
  "steps": [...]
}

// 최대 100건 보관, 초과 시 오래된 항목 자동 삭제

7. Git 자동화 페이지 (pages/git.php)

UI 페이지 접속: https://kiam.kr/vermanager/git?site=kiam-prod

vm-main
├── Git 저장소 정보 카드
│   ├── 브랜치: main
│   ├── 최신 커밋: 1cbf11c feat(vermanager): Phase 4-6...
│   ├── 변경 파일: 0개
│   ├── 최근 태그: v1.0.1, v1.0.0
│   └── 리모트: https://github.com/onlyonemaster/onlyopen.git
│
├── [Git 커밋] 섹션
│   ├── 커밋 메시지: [___________________________]
│   └── [커밋 실행] → POST /api/git (action=commit)
│
├── [Git 태그] 섹션
│   ├── 태그 버전: [______] (예: 1.0.2)
│   ├── 태그 메시지: [___________________________]
│   └── [태그 생성] → POST /api/git (action=tag)
│
├── [GitHub Push] 섹션
│   ├── 푸시 대상: origin/main (--tags 포함)
│   └── [Push 실행] → POST /api/git (action=push)
│
├── [전체 릴리즈] 섹션 (★ 권장)
│   ├── 버전: [______]
│   ├── 커밋 메시지: [___________________________]
│   ├── 태그 노트: [___________________________]
│   └── [전체 릴리즈 실행] → POST /api/git (action=full-release)
│
└── 최근 자동화 로그 (테이블)
    └── 시간 | 사이트 | 액션 | 상태 | 상세
💡 핵심 포인트: Git 자동화 API는 실제 shell_exec()로 git 명령을 실행합니다. 사이트 등록 시 document_root가 올바르게 설정되어 있어야 .git 디렉터리를 찾을 수 있습니다. 모든 git 명령은 작업 전 chdir($doc_root)로 디렉터리를 변경하고, 작업 후 원래 디렉터리로 복원합니다. full-release는 커밋할 변경사항이 없어도 태그와 Push는 정상 진행합니다.
