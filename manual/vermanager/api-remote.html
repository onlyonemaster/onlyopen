🖥️ 원격 서버 관리 API (api/remote.php)

Phase 4에서 구현된 원격 서버 연동 API입니다. SSH/TCP 기반 서버 상태 진단, 배포, 사이트 간 동기화를 지원합니다.

GET /vermanager/api/remote?action=ping&site=kiam-prod
GET /vermanager/api/remote?action=status&site=kiam-prod
GET /vermanager/api/remote?action=all-servers
POST /vermanager/api/remote — 배포/동기화

GET 액션

action설명반환
pingTCP 22번 포트 연결 테스트 (5초 타임아웃){ ok, reachable, host, latency_ms }
status서버 연결·버전·문서루트·디스크 용량 종합 진단{ ok, connection, ping, version:..., docroot_check, disk_info, recent_deploys }
all-servers모든 활성 사이트 서버 상태 일괄 조회{ ok, servers: [{site_id, status, ping, version}, ...] }
deploy-log최근 배포 로그 전체 조회 (최대 100건){ ok, site_id, logs: [...] }

POST 액션

action필수 파라미터설명
deploysite, version대상 서버에 버전 파일 배포. SSH 연결 → docroot 검증 → version.txt 생성 → 로그 기록.
syncfrom, to두 사이트 간 데이터 동기화. package.json, version_history.json, changelog.json, improvements.json 복사.

서버 처리 로직 (완전 추적)

// ── SSH 핑 (TCP 소켓) ──
function ssh_ping(string $host, int $port=22): array {
    $start = microtime(true);
    $socket = @fsockopen($host, $port, $errno, $errstr, 5);   // 5초 타임아웃
    $latency = round((microtime(true) - $start) * 1000);
    if ($socket) { fclose($socket); return ['reachable'=>true, 'latency_ms'=>$latency]; }
    return ['reachable'=>false, 'error'=>$errstr];
}

// ── 배포 대상 검증 ──
function check_deploy_target(string $docroot): array {
    // 1) 디렉터리 존재 확인
    // 2) 핵심 파일 존재 확인 (index.php, config.php, .htaccess)
    // 3) 디스크 용량 (disk_free_space, disk_total_space → MB)
    return [
        'docroot' => $docroot,
        'has_index'    => file_exists($docroot.'/index.php'),
        'has_config'   => file_exists($docroot.'/config.php'),
        'has_htaccess' => file_exists($docroot.'/.htaccess'),
        'disk_free_mb' => round(disk_free_space($docroot) / 1048576),
        'disk_total_mb'=> round(disk_total_space($docroot) / 1048576),
    ];
}

// ── 배포 실행 ──
function deploy(string $site_id, string $version): array {
    $site = get_site($site_id);
    $docroot = $site['document_root'] ?? '';
    $steps = [];

    // Step 1: SSH 연결 테스트
    $ping = ssh_ping($site['server_ip'] ?? '127.0.0.1');
    $steps[] = ['step'=>1, 'name'=>'SSH 접속 테스트', 'result'=>$ping['reachable']?'success':'fail'];

    // Step 2: 문서 루트 검증
    $target = check_deploy_target($docroot);
    $steps[] = ['step'=>2, 'name'=>'문서 루트 확인', 'result'=>'success', 'details'=>$target];

    // Step 3: 버전 파일 기록
    $version_path = $docroot . '/version.txt';
    file_put_contents($version_path, $version);
    $steps[] = ['step'=>3, 'name'=>'버전 파일 기록', 'result'=>'success', 'details'=>['version_file'=>$version_path]];

    // 배포 로그 저장 (최근 100건 유지)
    log_deploy($site_id, $version, $steps);

    return $steps;
}

// ── 사이트 간 동기화 ──
function sync_sites(string $from_id, string $to_id): array {
    $files = ['package.json', 'version_history.json', 'changelog.json', 'improvements.json'];
    $results = [];
    foreach ($files as $f) {
        $data = site_read_json($from_id, $f);
        site_write_json($to_id, $f, $data);
        $results[] = ['file'=>$f, 'synced'=>true];
    }
    return $results;
}
💡 핵심 포인트: SSH 핑은 실제 SSH 인증 없이 TCP 소켓 연결만 확인합니다. 배포 시 deploy()는 서버의 document_root에 version.txt 파일을 기록하여 현재 배포된 버전을 추적합니다. 배포 로그는 JSON 파일로 관리되며 최대 100건까지 보관됩니다. 동기화는 운영→개발 또는 개발→운영 양방향으로 가능합니다.
