🚀 릴리즈 API (api/release.php)

가장 핵심적인 API입니다. SemVer 버전 범핑, package.json 갱신, 버전 히스토리 기록, 소스 개선 연결, CHANGELOG 추가까지 6단계 원자적 트랜잭션을 수행합니다.

POST /vermanager/api/release

요청 Body (JSON)

필드타입필수설명
sitestring필수릴리즈 대상 사이트 ID. site-registry.json에 등록된 활성 사이트여야 함
typestring필수patch | minor | major
notestring선택릴리즈 노트. 버전 히스토리와 CHANGELOG에 기록됨
linked_improvementsstring[]선택연결할 소스 개선 ID 배열 (예: ["imp_4","imp_5"])
// 요청 예시
POST /vermanager/api/release
Content-Type: application/json

{

  "linked_improvements": ["imp_4", "imp_5"]

서버 처리 6단계 로직 (완전 추적)

  1. 메서드 검증

    POST만 허용. GET 등 다른 메서드는 405 + JSON 에러 반환. php://input에서 JSON Body 디코딩.

  2. 사이트 검증

    $_POST['site'] 또는 JSON body의 site 필드로 사이트 ID 확인 → get_site($site_id)로 등록부 조회 → 없으면 400 에러.

  3. 버전 범핑 (SemVer)

    site_get_current_version($site_id) → data/sites/{id}/package.json 읽기. bump_version($current, $type) 호출: MAJOR(하위 초기화: minor=0, patch=0), MINOR(patch=0), PATCH(+1).

  4. package.json 갱신

    site_write_json($site_id, 'package.json', $new_package) → 파일 덮어쓰기. version, lastRelease(현재시각), lastReleaseBy('아리아') 업데이트.

  5. 소스 개선 연결

    linked_improvements 배열 순회: improvements.json에서 해당 ID 항목 찾아 released_in 필드에 새 버전 기록. 각 개선 항목의 제목을 CHANGELOG 노트에 수집.

  6. 히스토리 & CHANGELOG 기록

    version_history.json에 새 항목 추가 (id=uniqid, from→to, type, date, note, linked_improvements). changelog.json에 버전별 변경사항 추가.

💡 핵심 포인트: 하나의 POST 요청으로 3개의 JSON 파일(package.json, version_history.json, changelog.json)이 동시에 갱신됩니다. linked_improvements가 있으면 improvements.json도 4번째로 갱신됩니다. 모든 작업은 PHP 파일 I/O 기반이므로 MySQL 트랜잭션 없이도 원자적으로 처리됩니다.
